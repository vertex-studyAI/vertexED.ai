# Multimodal Calibration Under Distribution Shift — Pre-outcome Protocol

**Status:** PRE_OUTCOME_PROTOCOL_ONLY — NOT AUTHORIZED TO RUN  
**Frozen:** 2026-09-04  
**Source branch:** `research/multimodal-calibration-preoutcome-20260904`  
**Origin:** follow-up to the 2026-09-03 research discussion with Daniel Lewis.  
**Claim boundary:** this document fixes the question, perturbation families, metrics, comparison logic, and falsifiers before any result-bearing execution. It is not evidence of model robustness, alignment, calibration quality, collaboration, external validation, or publication readiness.

## 1. Research question

For a fixed multimodal multiple-choice reasoning model, does predictive calibration degrade under controlled visual distribution shift before ordinary task accuracy degrades, and can a lightweight development-only temperature calibration reduce that degradation without improving the underlying task model?

The primary scientific object is **calibration and selective-risk behavior under image corruption/missingness**, not raw model superiority.

## 2. Task and data freeze

Use the image-present subset of the **ScienceQA** multiple-choice benchmark. Before execution, an authorization manifest must record:

- exact dataset release/revision and source URL or package revision;
- exact development/evaluation record IDs and ordered SHA-256 manifests;
- confirmation that temperature fitting uses development records only;
- exact exclusion rule for malformed/unloadable examples;
- model/provider revision and tokenizer/processor revision;
- exact inference precision, decoding/logit-extraction method, and dependency lock digest.

No evaluation record may be moved into the calibration-development set after any evaluation result is observed.

## 3. Predictive confidence

For each multiple-choice example, obtain one score per answer option from the fixed model using an execution-time method frozen before evaluation (prefer normalized option-token log probabilities when the model exposes logits). Convert the option scores to a probability simplex with a frozen softmax mapping.

If the chosen model/runtime cannot expose a reproducible option score for every choice, execution fails closed. Do not substitute post-hoc self-reported verbal confidence after seeing results.

## 4. Shift conditions

Evaluate the same frozen records under the following deterministic image conditions. The authorization manifest must freeze implementation/version and random seed before execution.

- **S0 — clean:** original image.
- **S1 — mild blur:** Gaussian blur, fixed radius `1.0`.
- **S2 — moderate blur:** Gaussian blur, fixed radius `2.0`.
- **S3 — severe blur:** Gaussian blur, fixed radius `4.0`.
- **S4 — central occlusion:** replace the centered 25% of image area with a constant neutral patch derived only from image-format conventions, not the example label.
- **S5 — image missingness:** replace the image with a fixed neutral placeholder of the original dimensions while leaving text/question/options unchanged.

All transforms are applied after the same deterministic resize/preprocessing entry point used by the fixed model. If a model processor performs additional stochastic transforms, they must be disabled or frozen.

## 5. Compared methods

### B0 — Uncalibrated model
Use the fixed raw option probabilities with no post-hoc calibration.

### B1 — Development-only temperature scaling
Fit a single scalar temperature `T > 0` on the clean **development** records by minimizing negative log likelihood. Freeze the optimizer, bounds, stopping rule, fitted `T`, and fit-set digest before opening evaluation metrics. Apply the same fitted `T` unchanged to S0–S5.

B1 is a calibration intervention only. It must not change prompts, model weights, retrieved context, answer options, or image transforms.

## 6. Metrics

Report every condition separately for B0 and B1.

**Primary calibration metrics**
- multiclass Brier score;
- negative log likelihood (NLL);
- expected calibration error (ECE) using a preregistered equal-width bin count fixed in the authorization manifest.

**Task metric**
- multiple-choice accuracy.

**Selective prediction metrics**
- area under the risk–coverage curve (AURC), with risk = error rate;
- accuracy at fixed 80%, 60%, and 40% coverage, retaining the highest-confidence predictions;
- coverage attainable at a preregistered target risk recorded in the authorization manifest.

**Diagnostics**
- mean confidence;
- confidence gap between correct and incorrect predictions;
- per-shift confusion/error counts;
- protocol-error count and excluded-record count with reasons.

Do not replace the primary metrics after observing outcomes.

## 7. Central hypothesis and falsification logic

The specific hypothesis is that visual shift can produce a **calibration warning before a comparable accuracy collapse**.

For each shift relative to S0, compute:

- relative change in Brier score, NLL, and ECE;
- absolute change in accuracy;
- change in AURC.

The “calibration degrades before accuracy” hypothesis is **not supported** if there is no preregistered corruption step at which calibration/selective-risk deterioration is materially larger than the accompanying accuracy deterioration under the frozen decision rule defined in the authorization manifest.

Temperature scaling is **not supported as shift-robust calibration** if B1 fails to improve the preregistered primary calibration aggregate versus B0 across the frozen shifted conditions, or if any apparent gain is explained only by clean S0 performance while shifted conditions worsen materially.

A null, negative, mixed, or assumption-breaking outcome is valid and must be retained unchanged.

## 8. Statistics and uncertainty

Before execution, freeze:

- bootstrap seed;
- bootstrap replicate count (minimum 2,000 unless compute is infeasible before outcome access);
- exact aggregation rule across S1–S5;
- ECE bin count;
- the quantitative decision rule for “materially larger” calibration deterioration;
- target risk for selective coverage.

Use paired record-level bootstrap resampling when comparing B0 and B1 or one shift against S0. Report two-sided 95% confidence intervals. Do not introduce significance tests or new thresholds after results are visible.

## 9. Required ablations / controls

- clean S0 calibration for both B0 and B1;
- corruption severity trend across S1–S3;
- occlusion S4 versus missingness S5;
- B0 versus B1 under the exact same frozen examples and transforms;
- optional text-only control only if frozen in a separate amendment **before** evaluation outcomes are opened.

## 10. Evidence and reproducibility requirements

The execution package must retain:

No missing or failed example may be silently dropped after outcomes are observed.
