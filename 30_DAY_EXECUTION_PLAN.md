# 30-DAY EXECUTION PLAN

**Start:** 2026-08-14  
**Goal:** fewer active projects, stronger evidence, finished negative-result packages, validated products, trustworthy Percy state.

## Concurrency caps

- At most **3 major scientific experiments** concurrently.
- At most **2 paper conversions** concurrently.
- At most **2 product validation programmes** concurrently.
- Negative-result packaging and documentation may proceed without consuming an experiment slot if no new scientific result is generated.

## Week 1 — compression, provenance and decisive protocol freezes

### Paper conversions — max 2
1. **LAM-JEPA:** close related work, authorship/license/provenance, generate final tables/figures strictly from retained artifacts, run skeptical review.
2. **IRIS v0.2:** assemble negative/tradeoff manuscript skeleton from frozen evidence; no successor experiment.

### Scientific experiment slots — max 3
1. **NeuroCAD:** preregister same-provider learned direct-generation vs typed-IR comparison; freeze OOD set and validity metrics before execution.
2. **T2424-0027:** freeze one real multilingual encoder leakage audit with negative controls.
3. Keep third slot **empty** unless Darcy baseline harness is fully frozen and cheap.

### Products — max 2
1. **FinanceMeta:** apply authorization hardening on isolated branch, add meaningful regression tests/CI where feasible; do not apply production migration without production access.
2. **VertexED:** resolve exact served revision identity and disposable authenticated certification; no feature expansion.

### Percy
- Read existing host SQLite/WAL/process state before scheduler changes.
- Measure queue counts, lease state, duplicate dispatch, failure/stale counts, provider/API throughput, CPU/RAM pressure and verifier capacity.
- Preserve failed runs; no reset and no worker-count increase.

## Week 2 — baseline/ablation/reproduction attacks

1. Execute frozen NeuroCAD comparison; retain raw generations, syntax/geometry/execution outcomes, provider/model identity, costs and hashes.
2. Execute frozen T2424-0027 real-encoder study. If effect disappears, close as negative transfer result rather than retuning probes.
3. If a scientific slot opens, freeze/run Darcy matched-budget FNO/DeepONet-family or comparable learned operator baseline plus OOD/misaligned regime.
4. Independently reproduce LAM-JEPA final package from clean checkout/worktree.
5. Recompute manuscript tables/figures independently from raw artifacts.
6. Package NGMT v0.1 and T2424-1863 negative results without new tuning.
7. Percy: bounded crash/restart/checkpoint/stale-task/duplicate-suppression qualification; record measured throughput and cost accounting.

## Week 3 — manuscripts and external/product validation

### Papers
- LAM-JEPA: reviewer attack, claim-to-artifact provenance audit, preprint/technical-report candidate.
- NeuroCAD: only enter manuscript conversion if learned/OOD gates support a contribution; otherwise preserve negative/engineering result.
- IRIS: complete negative/tradeoff report only if novelty/context survives originality review.

### External validation
- Send LAM package to one independent reviewer/reproducer.
- Send NeuroCAD benchmark to one CAD/program-synthesis reviewer if Week 2 gate survives.
- Send one Project 2424 candidate only, not the entire registry.

### Product validation
- VertexED: real disposable-user create → save → fresh-session retrieve → logout/access-denial journey tied to exact deployment SHA.
- FinanceMeta: preview/production-equivalent member role-escalation attack plus golden journey after migration is available.
- If one product slot frees, certify The Bu1LD immutable deployment/hydration and seven-role boundaries.

## Week 4 — release/submission candidates and next gates

1. Cut LAM-JEPA release candidate only when provenance, figures/tables, reproduction and independent review are complete.
2. Decide NeuroCAD: `A PUBLISH`, `B PRODUCTIZE`, `D NEGATIVE`, or `E ARCHIVE` based on learned/OOD evidence.
3. Decide T2424-0027 and Darcy independently; promote at most one to the next flagship slot unless both clearly clear gates.
4. Publish compact negative-result packages for NGMT/T2424-1863 if scientifically useful; otherwise archive with reproduction bundles.
5. VertexED/FinanceMeta/Bu1LD: release only claim-specific production states actually verified.
6. Percy: freeze a measured scheduler operating envelope; document safe concurrency from observed bottlenecks rather than logical registry size.
7. Re-score all Tier A projects and keep at most five Tier S / ten Tier A.
8. Update kill list; do not refill capacity with speculative new projects.

## Daily operating loop

1. **Recover:** inspect current branch/head, host/task state and last artifacts.
2. **Verify:** confirm what changed against code/results, not status labels.
3. **Prioritize:** choose smallest decisive task by information gain × closure probability.
4. **Execute:** no vague investigation tasks.
5. **Independent verify:** separate authoring from certification where possible.
6. **Update evidence:** raw outputs, config, hash, source commit, runtime.
7. **Update claims:** only supported claim language.
8. **Kill/promote:** explicit state transition.
9. **Queue next dependencies:** no speculative filler.

## Day-30 success criteria

- Tier S remains <=5 and active research is materially smaller.
- LAM-JEPA has a defensible finished negative-result package or a documented external-review blocker.
- NeuroCAD has either survived strong learned/OOD controls or been honestly demoted.
- At least one Project 2424 child has passed a real external/strong-baseline gate, or the slot remains empty.
- NGMT/IRIS/Eigen/T2424-1863 negative outcomes remain preserved without rescue tuning.
- VertexED exact deployment status is known; FinanceMeta authorization boundary is fixed/tested in source; Bu1LD live state is either certified or precisely blocked.
- Percy host counters and bottlenecks are measured from the persistent state and safe concurrency is evidence-derived.
