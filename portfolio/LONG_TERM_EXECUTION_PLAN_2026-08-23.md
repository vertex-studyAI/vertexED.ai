# Portfolio Long-Term Execution Plan — 2026-08-23

## Purpose

This document is the strategic execution layer above the evidence-first command center. It does **not** redefine a project as green, launched, healthy, validated, partnered, or complete. Those claims remain controlled by the project-specific evidence gates and canonical status artifacts.

## Portfolio operating law

1. Keep at most **three foreground execution lanes** at a time.
2. Revenue, real-user evidence, production reliability, and independently reproducible research outrank feature count or send volume.
3. A passing build is not a launch. A sent email is not a pilot. A reply is not validation. A meeting is not a partnership. A generated result is not a scientific result until provenance and reproduction gates are satisfied.
4. Do not retune, relabel, or selectively rerun frozen negative/mixed research to rescue a desired claim.
5. Do not spread NVIDIA branding or benefits beyond the entity and program membership that can actually be verified.
6. Prefer one durable canonical control artifact per lane over parallel conflicting plans.

# Horizon 2 — December 2026 through August 2027

## Portfolio concentration

By this point every major project should fall into one of four dispositions:

- **Scale** — validated product/research program with repeat usage or external evidence.
- **Maintain** — useful but not a growth priority.
- **Incubate** — explicitly bounded experiment with a decision date.
- **Archive/freeze** — no active execution except preservation, publication, or reproducibility work.

Do not allow every idea to remain permanently 'active.'

## Product / venture objectives

- VertexED: repeatable paid acquisition or institutional distribution, measured retention, support reliability, and clear unit economics.
- NeuroCAD: design-partner traction sufficient to justify a product spinout, or a deliberate research-tool disposition.
- FinanceMeta / Bu1LD: institutional systems that function without constant founder intervention.
- Obscured Records: repeatable client economics and documented delivery system.
- Commerce: retain only niches that survive fulfillment and margin evidence.

## Infrastructure objectives

- Percy: portfolio control plane with actual durable state and reliable agents.
- Olympus: treat large-model ambitions as staged research engineering; advance Hermes → Prometheus → larger stages only when hardware, datasets, evals, and smaller-stage evidence justify it.
- Ultron: resolve canonical identity and intended product/research role; archive it if that cannot be made concrete.

## HomeLab / physical AI

Expand hardware only in service of defined experiments. Sequence:

1. fabrication/electronics safety and basic tooling;
2. repeatable sensor/edge-ML experiments;
3. robotics and computer-vision prototypes;
4. physical-AI research workloads;
5. only then more ambitious wearable/BCI-adjacent prototypes, with appropriate medical/electrical safety boundaries and no unsafe human experimentation.

# Weekly portfolio cadence

## Monday — truth + priorities

- Refresh production/research evidence.
- Select exactly three foreground outcomes.
- Freeze lower-value work that competes with them.

## Daily — execution

- Reliability incident first.
- Warm reply/requested action second.
- Active pilot/customer/research reproduction third.
- New cold outbound only after the above are clear.

## Friday — disposition review

For each active lane record:

- verified delta this week;
- money/users/external evidence created;
- blocker owner;
- next irreversible step;
- continue / pause / archive decision.

# Portfolio scoreboard

Track these, not agent or email volume:

- production incidents open / closed with evidence;
- authenticated real-user journeys verified;
- qualified conversations;
- demos;
- active pilots;
- paid customers/clients;
- fulfilled orders;
- week-1 and month-1 retention where applicable;
- external engineering/research reproductions;
- papers with claim/evidence alignment;
- security blockers;
- projects moved to Scale / Maintain / Incubate / Archive.

## Final rule

The portfolio is not finished when every repository has more code. It is finished when the important systems have verifiable reliability, real external use, defensible research evidence, and a small number of projects that deserve sustained scale.
